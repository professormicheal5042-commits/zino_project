Zero-Knowledge Architecture Explained
How ZINO guarantees that your data is mathematically private.
A
AES-256-GCM Key Generation
When you upload a file, your browser dynamically generates a unique 256-bit AES key using the crypto.subtle.generateKey() Web Crypto API. This key never leaves your browser in plain form.
↓
B
File Encryption (AES-GCM)
Your file is encrypted entirely in-browser into an unreadable cipher-blob using a random 96-bit Initialization Vector (IV). The IV ensures that even identical files produce completely different ciphertexts.
↓
C
RSA-4096 OAEP Key Wrapping
The AES session key is "wrapped" (encrypted) using your RSA-4096 Public Key via the OAEP padding scheme. This means only your corresponding RSA Private Key (.pem file) can ever unwrap it.
↓
D
Secure Upload to Supabase
Only three things are stored on the ZINO server: the encrypted cipher-blob, the RSA-wrapped AES key, and the IV. The server sees zero plain-text data — even a compromised database reveals nothing without your private key.
Zero-Knowledge
The server knows absolutely nothing about your plain-text data or private keys.
AES-GCM
Advanced Encryption Standard in Galois/Counter Mode — provides both confidentiality and data authenticity.
RSA-OAEP
Optimal Asymmetric Encryption Padding — prevents deterministic chosen-plaintext attacks.
Web Crypto API
Native browser API ensuring cryptographic operations happen in non-extractable secure memory — no JavaScript extension can steal your keys.
